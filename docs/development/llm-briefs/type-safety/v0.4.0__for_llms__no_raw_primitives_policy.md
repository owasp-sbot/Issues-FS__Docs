# No Raw Primitives Policy

- **version**: v0.4.0
- **updated**: February 2026
- **scope**: All Issues-FS ecosystem code (production and test)
- **prerequisite**: Familiarity with the Type_Safe & Python Formatting Guide and the Collections Subclassing Guide

---

## Policy Statement

**Raw Python primitives are banned from type annotations in the Issues-FS ecosystem.** The following built-in types must never appear as field types, parameter types, or return types in any `Type_Safe` class or `@type_safe`-decorated method:

| Banned Type | Replacement Category | Examples |
|------------|---------------------|----------|
| `str` | `Safe_Str__*` domain primitives | `Safe_Str__Text`, `Safe_Str__Node_Label`, `Safe_Str__File__Path` |
| `int` | `Safe_Int__*` or `Safe_UInt` | `Safe_UInt`, `Timestamp_Now`, custom `Safe_Int__*` |
| `float` | `Safe_Float__*` | `Safe_Float`, custom `Safe_Float__*` |
| `list` / `List[...]` | `Type_Safe__List` subclass | `List__Node__Ids`, `List__Event__Log` |
| `dict` / `Dict[...]` | `Type_Safe__Dict` subclass | `Dict__Nodes__By_Id`, `Dict__Nodes__By_Label` |
| `set` / `Set[...]` | `Type_Safe__Set` subclass | `Set__Permission__Ids` |
| `tuple` / `Tuple[...]` | `Type_Safe__Tuple` subclass | `Tuple__Coordinates__3D` |
| `bool` | `bool` is allowed | `bool` is the one exception -- it is permitted |

**`bool` is the sole exception.** Boolean fields and parameters may use raw `bool` because there is no `Safe_Bool` variant, and the explicit `is True` / `is False` convention already provides sufficient safety.

---

## Why Raw Primitives Are Banned

### 1. Runtime Type Safety Is Lost

Raw primitives carry no semantic meaning. A `str` could be a file path, a node label, a status, a UUID, or any other string. Type_Safe cannot enforce constraints on raw types:

```python
# DANGEROUS: Any string accepted -- no validation, no context
class Schema__Node(Type_Safe):
    label     : str                                                    # Could be anything
    file_path : str                                                    # Could be anything
    status    : str                                                    # Could be anything

# SAFE: Each field has domain-specific validation
class Schema__Node(Type_Safe):
    label     : Safe_Str__Node_Label                                   # Must match label format
    file_path : Safe_Str__File__Path                                   # Must be valid file path
    status    : Safe_Str__Status                                       # Must be valid status value
```

### 2. @type_safe Cannot Enforce Contracts

The `@type_safe` decorator checks parameter types at runtime. With raw `str`, any string passes. With `Safe_Str__Node_Label`, only valid labels pass:

```python
# DANGEROUS: accepts any string, including malformed input
@type_safe
def get_node_by_label(self, label: str) -> Schema__Node:
    ...

# SAFE: rejects invalid labels at the method boundary
@type_safe
def get_node_by_label(self, label: Safe_Str__Node_Label) -> Schema__Node:
    ...
```

### 3. Collections Lose Type Enforcement

When `Dict[str, X]` is used in a Type_Safe class, the framework converts it to `Type_Safe__Dict` at runtime. But the `str` key type provides no validation -- any string is accepted as a key. With a proper `Safe_Str__*` or `Node_Id` key type, invalid keys are rejected:

```python
# DANGEROUS: any string accepted as key
class Schema__Data(Type_Safe):
    nodes : Dict[str, Schema__Node]                                    # Key could be anything

# SAFE: only valid Node_Id values accepted as keys
class Dict__Nodes__By_Id(Type_Safe__Dict):                             # Named, reusable type
    expected_key_type   = Node_Id
    expected_value_type = Schema__Node

class Schema__Data(Type_Safe):
    nodes : Dict__Nodes__By_Id                                         # Self-documenting, type-enforced
```

### 4. Node_Id and Edge_Id Require Explicit Construction

A critical subtlety: `Node_Id()` with no arguments returns an **empty string**, not an auto-generated ID. This is by design -- `Node_Id` is meant to be assigned explicitly. Only `Obj_Id()` auto-generates random hex IDs.

When code uses `str` for node ID keys, it bypasses this distinction. Using `Node_Id` as the key type makes the contract explicit and catches empty-ID bugs at the collection boundary.

```python
# BUG: Node_Id() creates empty string '', all nodes share same key
node_id = Node_Id()                                                    # node_id == ''
data.nodes[str(node_id)] = node1                                      # key == ''
data.nodes[str(node_id)] = node2                                      # overwrites node1!

# CORRECT: Use Obj_Id to generate unique IDs, Node_Id to wrap them
node_id = Node_Id(Obj_Id())                                           # node_id == 'a3f7c201'
```

## Replacement Reference

### String Types

| Raw Type | When the string represents... | Use Instead |
|----------|------------------------------|-------------|
| `str` | Generic text | `Safe_Str__Text` |
| `str` | File or folder path | `Safe_Str__File__Path` |
| `str` | Node display label (e.g., "Task-6") | `Safe_Str__Node_Label` |
| `str` | Node type (e.g., "task", "bug") | `Safe_Str__Node_Type` |
| `str` | Status value (e.g., "todo", "done") | `Safe_Str__Status` |
| `str` | Unique node identifier | `Node_Id` |
| `str` | Unique edge identifier | `Edge_Id` |
| `str` | Unique object identifier | `Obj_Id` |
| `str` | Generic identifier | `Safe_Id` |
| `str` | Hash value | `Safe_Str__Hash` |
| `str` | New domain concept | Create a new `Safe_Str__*` subclass |

### Numeric Types

| Raw Type | When the number represents... | Use Instead |
|----------|------------------------------|-------------|
| `int` | Unsigned count or index | `Safe_UInt` |
| `int` | Timestamp | `Timestamp_Now` |
| `int` | New domain concept | Create a new `Safe_Int__*` subclass |
| `float` | Any float value | `Safe_Float` or a new `Safe_Float__*` subclass |

### Collection Types

| Raw Type | Use Instead | How |
|----------|-------------|-----|
| `Dict[str, X]` | `Type_Safe__Dict` subclass | Create `Dict__Items__By_Name(Type_Safe__Dict)` with `expected_key_type` and `expected_value_type` |
| `Dict[K, V]` (inline) | `Type_Safe__Dict` subclass | Same pattern -- define once, use as field type |
| `List[X]` | `Type_Safe__List` subclass | Create `List__Node__Ids(Type_Safe__List)` with `expected_type` |
| `List[X]` (inline, one-off) | `Type_Safe__List` inline | Acceptable for one-off usage if collection is not reused |
| `Set[X]` | `Type_Safe__Set` subclass | Create `Set__Tags(Type_Safe__Set)` with `expected_type` |
| `list` (bare) | Never use bare `list` | Always specify element type |
| `dict` (bare) | Never use bare `dict` | Always specify key/value types |

## Creating New Safe Primitive Types

When no existing `Safe_Str__*` type matches your domain concept, create a new one. This is encouraged -- the more domain-specific types we have, the stronger our runtime contracts:

```python
# Example: create a Safe_Str__Edge_Type for edge classification
from osbot_utils.type_safe.Type_Safe__Primitive                                   import Type_Safe__Primitive

class Safe_Str__Edge_Type(Type_Safe__Primitive, str):                  # Edge type classifier
    def __new__(cls, value=''):
        return str.__new__(cls, value)
```

Place the new primitive in the appropriate module under `issues_fs/schemas/` or alongside the classes that use it. Follow the `Safe_Str__Domain__Concept` naming convention.

## Creating Collection Subclasses

When a `Dict`, `List`, or `Set` is reused or has semantic meaning, define a named subclass:

```python
from osbot_utils.type_safe.type_safe_core.collections.Type_Safe__Dict             import Type_Safe__Dict
from osbot_utils.type_safe.primitives.domains.identifiers.Node_Id                 import Node_Id

class Dict__Nodes__By_Id(Type_Safe__Dict):                             # node_id -> node schema
    expected_key_type   = Node_Id
    expected_value_type = Schema__MGraph__Issue__Node

class Dict__Nodes__By_Label(Type_Safe__Dict):                          # label -> node_id
    expected_key_type   = Safe_Str__Node_Label
    expected_value_type = Node_Id

class Dict__Children__By_Parent(Type_Safe__Dict):                      # parent_id -> list of child_ids
    expected_key_type   = Node_Id
    expected_value_type = List__Node__Ids
```

See the full guide: `v3.63.3__for_llms__type_safe__collections__subclassing_guide.md`

## Common Anti-Patterns and Fixes

### Anti-Pattern 1: Raw `str` in Dict Keys

```python
# WRONG
nodes : Dict[str, Schema__Node]                                        # Raw str key

# CORRECT
class Dict__Nodes__By_Id(Type_Safe__Dict):
    expected_key_type   = Node_Id
    expected_value_type = Schema__Node

nodes : Dict__Nodes__By_Id
```

### Anti-Pattern 2: Raw `str` Parameters in Methods

```python
# WRONG
@type_safe
def get_node_by_path(self, path: str) -> Schema__Node:                 # Raw str parameter
    ...

# CORRECT
@type_safe
def get_node_by_path(self, path: Safe_Str__File__Path) -> Schema__Node:
    ...
```

### Anti-Pattern 3: Raw `str` Return Types

```python
# WRONG
@type_safe
def add_node(self, node: Schema__Node) -> str:                         # Raw str return
    ...

# CORRECT
@type_safe
def add_node(self, node: Schema__Node) -> Node_Id:                     # Typed return
    ...
```

### Anti-Pattern 4: Raw `Dict[str, str]` for Indexes

```python
# WRONG
class MGraph__Domain(Type_Safe):
    index_by_label : Dict[str, str]                                    # Two raw str types
    index_by_path  : Dict[str, str]                                    # Two raw str types

# CORRECT
class Dict__Index__By_Label(Type_Safe__Dict):
    expected_key_type   = Safe_Str__Node_Label
    expected_value_type = Node_Id

class Dict__Index__By_Path(Type_Safe__Dict):
    expected_key_type   = Safe_Str__File__Path
    expected_value_type = Node_Id

class MGraph__Domain(Type_Safe):
    index_by_label : Dict__Index__By_Label                             # Self-documenting
    index_by_path  : Dict__Index__By_Path                              # Self-documenting
```

### Anti-Pattern 5: Raw `List[str]` for ID Collections

```python
# WRONG
class MGraph__Domain(Type_Safe):
    index_by_parent : Dict[str, List[str]]                             # Raw str everywhere

# CORRECT
class List__Node__Ids(Type_Safe__List):
    expected_type = Node_Id

class Dict__Children__By_Parent(Type_Safe__Dict):
    expected_key_type   = Node_Id
    expected_value_type = List__Node__Ids

class MGraph__Domain(Type_Safe):
    index_by_parent : Dict__Children__By_Parent                        # Fully typed
```

### Anti-Pattern 6: Using Node_Id() Without a Value

```python
# WRONG: Node_Id() returns empty string ''
node = Schema__Node(node_id=Node_Id())                                 # node_id == ''

# CORRECT: Use Obj_Id() to generate, then wrap in Node_Id
node = Schema__Node(node_id=Node_Id(Obj_Id()))                        # node_id == 'a3f7c201'

# ALSO CORRECT: Use Node_Id.from_seed() for deterministic IDs
node = Schema__Node(node_id=Node_Id.from_seed('test-node-1'))         # node_id == 'ed1e1dcf'
```

## Audit Checklist

When reviewing code for raw primitive violations:

- [ ] **Field annotations**: Check every `: str`, `: int`, `: float`, `: list`, `: dict`, `: set`, `: tuple` in Type_Safe classes
- [ ] **Dict key types**: Check every `Dict[str, ...]` -- the `str` key should be a `Safe_Str__*` or `Node_Id`/`Edge_Id`
- [ ] **Dict value types**: Check every `Dict[..., str]` -- the `str` value should be typed
- [ ] **Method parameters**: Check every `param: str` in `@type_safe` methods
- [ ] **Method returns**: Check every `-> str`, `-> int`, `-> dict`, `-> list` return type
- [ ] **List element types**: Check every `List[str]` -- should use `Safe_Str__*` or domain type
- [ ] **Inline Dict/List**: Check if inline `Dict[K, V]` or `List[X]` should be a named subclass
- [ ] **Node_Id/Edge_Id construction**: Ensure `Node_Id()` and `Edge_Id()` are never called without a value (use `Node_Id(Obj_Id())` or `Node_Id.from_seed(...)`)

## Scope and Exceptions

### In Scope

- All production code in `issues_fs/` directories
- All schema classes (`Schema__*`)
- All service classes (`*__Service`)
- All domain classes (`*__Domain`)
- All graph/MGraph classes
- All Type_Safe class field annotations
- All `@type_safe` method parameters and return types

### Exceptions

- **`bool`**: Raw `bool` is permitted (explicit `is True`/`is False` convention provides safety)
- **`str()` function calls**: Using `str(x)` to convert a value is fine -- the ban is on `str` as a TYPE ANNOTATION
- **`-> None` return type**: `None` is not a primitive in this context
- **`-> int` for len/count**: Methods like `node_count() -> int` are acceptable since the return is a plain count
- **Local variables**: Local variables without type annotations are not subject to this policy
- **Test assertions**: `assert type(x) is str` in tests is fine -- it's testing, not annotating
- **Typing imports**: `from typing import Dict, List` is fine -- it's the USAGE of raw types in annotations that's banned
